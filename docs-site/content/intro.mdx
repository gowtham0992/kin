## One reply, understood by the family

Someone can say that their check-in is done, not done yet, or intentionally
skipped. Kin records the reported reply; it does not infer how the person is
feeling or decide whether they are safe.

The family can see the plan and agree who is on duty. When automatic follow-up
processing is enabled and routing is ready, an overdue check-in can prompt a
discreet notification to the assigned caregiver. Acknowledging that follow-up
records **seen**, not contacted, completed or safe.

Weekly notes bring recorded activity together, with source facts you can
inspect instead of an unexplained score.

## Choose how to use Kin

- **For the person checking in:** use a linked Echo, or speak, type or choose a
  reply in Kin's web conversation. Review the proposed change before saving.
- **For caregivers:** open the shared family workspace on a phone or computer.
  It can be added to a phone's home screen; there is no separate app-store download.
- **For builders and reviewers:** run the isolated local story, then explore
  the [MCP integration](./echo-and-mcp.md) and [developer overview](./for-developers.md).

The hosted family workspace requires authorized sign-in and accepted circle
membership. A roster name is not an account, and this documentation does not
grant access.

## Know the boundaries

The working Echo connection is a **classic Alexa development skill**. Kin's
browser conversation uses real MCP calls, but it is not Amazon's Alexa+
interface or proof of native Alexa+ Toolkit access. The local story uses
synthetic people, time and notifications.

General recurring missed-check-in processing is currently off in the hosted
deployment. A notification demonstration or successful test is not a promise
that automatic delivery is always running.

Kin coordinates ordinary family care. It is not a medical device, medication
adviser, fall detector, emergency monitor or replacement for a call.
